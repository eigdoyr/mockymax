# v0.2 → v0.2.5 Architecture Pivot

## Decision

Migrate MockyMax from quad-based homography compositing to alpha-mask compositing.

## Context

v0.2 was planned around a "screen quad" approach: each scene defines 4 corner coordinates of the screen region, and the compositor uses a perspective homography to warp the user's screenshot into that quad.

By the time we were halfway through v0.2 (6 of 12 issues complete), real product limitations became visible:

- Rounded screen corners can't be represented as a 4-point quad. Screenshots leak past the curve.
- Partially visible screens (phone in pocket, laptop at angle in alcove) require cropping the screenshot to match the visible region. Quads can't express this.
- Manual corner-picking is tedious and error-prone, especially for the 14 winning scenes from the viability test (issue #34).
- Auto-detection by white-region scanning works only when the screen is dominant in the image, which excludes editorial compositions where the screen is small or partial.

## What the industry actually does

The premium mockup tools (Mockuuups Studio, Shots.so, Photoshop Smart Object mockups) do not use quad warping. They use **alpha masks** — a separate image per scene where white pixels mark the screen area, black pixels mark the background, and gray pixels handle anti-aliased edges including rounded corners.

At render time:

1. Draw background
2. Draw user screenshot warped/scaled to fit
3. Blend through alpha mask

This handles rounded corners, partial screens, soft edges, and (in extended form) reflections and glare layers — all natively.

## The masks come from where

We validated using Meta's Segment Anything Model 3 (SAM 3) via Fal.ai (`fal-ai/sam-3/image`). The model accepts an image and a text prompt ("screen of the device") and returns a pixel-accurate mask. Cost: $0.005 per image. Industry-standard model used by Adobe, Figma, and major e-commerce platforms.

## Evidence

We ran SAM 3 on three representative images from the viability test:

- `monitor-linen-overcast-01` (full visible monitor)
- `phone-pocket-denim-01` (partially visible phone in jeans pocket)
- `laptop-alcove-tungsten-01` (laptop in dramatic shadow)

All three produced **perfect masks** including rounded corners and the partial-visibility case. Sample evidence in `docs/v0.2.5-pivot-evidence/`.

Total validation cost: $0.015.

## Pivot trigger

Pre-defined: pivot if SAM 3 produced usable masks for ≥70% of test images. Actual result: 100% on a 3-image sample.

## What this means for v0.2

The v0.2 milestone is being closed as an "early prototype" phase. Completed work (#29–#34) remains in the codebase. Some of that work (homography, quad-based compositing, corner-picking detection) will be removed in v0.2.5.

The 14 winning images selected in issue #34 do not need to be regenerated. They're reused as-is, with masks generated by SAM 3.

## What this means for v0.2.5

New milestone. New compositor (alpha-mask, WebGL). New scene format (v2, mask asset replacing screen quad). New Scene Studio that triggers SAM 3 segmentation instead of corner picking.

Issue list to be drafted under the v0.2.5 milestone.

## What this means for v0.3+

With the alpha-mask architecture in place, future quality improvements become straightforward:

- Reflection/glare overlay layers on top of screenshots
- Per-scene color grading to match scene lighting
- Multi-screen scenes (two devices in one composition)
- User-adjustable screenshot positioning/scaling within the mask
